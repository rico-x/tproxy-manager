## Изменения / Changes

### Русский

Релиз исправлений, найденных при полной проверке интерфейса.

**Исправления**

- Подписки, отвечающие сжатыми (gzip) данными, снова обновляются. Раньше такая подписка не загружалась вообще, а текстовые работали и скрывали проблему.
- Из-за той же причины роутер накапливал временные каталоги и со временем мог заполнить `/tmp`. Теперь они удаляются на всех путях, а оставшиеся от прежних версий подчищаются автоматически.
- Настройки Watchdog снова сохраняются: раньше любое сохранение завершалось сообщением о пустом обязательном поле.
- Кнопка `Проверить все ссылки` больше не заканчивается ошибкой шлюза. Проверка идёт в фоне: кнопка отвечает сразу, результаты появляются в таблице по мере готовности, повторный запуск во время проверки отклоняется.
- Кнопка `Отменить изменения` на вкладке `TPROXY` действительно сбрасывает несохранённые правки.
- Кнопки `Применить` и `Отмена` при восстановлении из резервной копии больше не отклоняются с сообщением о недействительном маркере безопасности.

**Безопасность**

- Служебные каталоги обновления proxy-ядер — копия предыдущего бинаря и кэш списка релизов — больше нельзя подменить. Локальный процесс мог заранее создать их в `/tmp` и подставить свой файл, который роутер затем установил бы как ядро и запустил, либо подменить ссылку, с которой скачивается сборка. Каталоги создаются и проверяются как принадлежащие только root, кэш читается лишь тогда, когда записать его мог только root, а запись выполняется атомарно.

**Интерфейс**

- Неудачи больше не показываются зелёным сообщением, которое само исчезает: неуспешное обновление GEO и результат вида `Обновлено 0 из 3 источников` теперь ошибки.
- Сообщения об успехе и об ошибке больше не появляются на странице одновременно; отмена убирает сообщение от предыдущего действия.
- Подтверждение удаления файла в редакторах конфигурации ядер называет файл. Список после других действий возвращается к первому файлу, поэтому подтверждение могло относиться не к тому файлу, который был открыт.

### English

A fix release for problems found while exercising every function of the UI.

**Fixes**

- Subscriptions that answer with compressed (gzip) data update again. Previously such a subscription could not be fetched at all, while plain-text ones kept working and hid the problem.
- The same cause made the router accumulate temporary directories, which could eventually fill `/tmp`. They are now removed on every path, and leftovers from earlier versions are cleaned up automatically.
- Watchdog settings can be saved again: previously every save ended with a message about an empty required field.
- The `Check all links` button no longer ends in a gateway error. The scan runs in the background: the button answers immediately, results appear in the table as they arrive, and starting a second scan while one is running is refused.
- The `Cancel changes` button on the `TPROXY` tab now really discards unsaved edits.
- The `Apply` and `Cancel` buttons in backup restore are no longer rejected with a message about an invalid security token.

**Security**

- The proxy engine update directories - the copy of the previous binary and the release list cache - can no longer be substituted. A local process could pre-create them in `/tmp` and plant a file that the router would then install as the engine and start, or redirect the URL a build is downloaded from. The directories are created and verified as belonging to root alone, the cache is read only when root alone could have written it, and writes are atomic.

**UI**

- Failures no longer appear as a green message that fades away on its own: a failed GEO update, and a result such as `Updated 0 of 3 sources`, are now errors.
- Success and error messages no longer appear on the page at the same time, and cancelling clears the message left by the previous action.
- The delete confirmation in the engine config editors names the file. The list returns to the first file after other actions, so the confirmation could apply to a file other than the one that was open.
